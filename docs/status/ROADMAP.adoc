= Roadmap

== 0.1.0 (current)

* Receipts split into standpoint, warrant and projection, with a
  digest over a canonical JSON form that makes accidental edits evident.
* A one-column wire form for carrying receipts in CSV and ECSV tables.
* `epi_status`, decided in a fixed order: digest, then gates, then rank.
* Per-rank threshold policies for DADA2 and vsearch, held as data.
* Residuals in which "novel" is reachable only after the contamination gate.
* `can_merge`, which compares two runs over the judgement surface only and
  refuses when they share no rank.
* Tested by Aqua and the behaviour suite. The limits below are pinned by tests.

== Candidates for the next release

These are open. Their order is not fixed. Each one is described in
link:../EXPLAINME.adoc#_current_limits[Current limits].

Claimed versus warranted rank::
Have `epi_status` compare the rank a receipt claims with the rank its warrant
clears, and demote when they differ.

Per-rank bootstrap::
Accept a bootstrap per rank instead of a single `boot_min`, so DADA2 output can
be read directly.

More classifier policies::
Policy tables for QIIME 2's naive Bayes classifier and SINTAX, whose rows are
currently `:Belief` at best.
