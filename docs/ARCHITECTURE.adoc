= EpistemicTypes.jl architecture
:toc:

How the package is put together. The reasons behind the design are in
link:EXPLAINME.adoc[EXPLAINME]. The file-by-file inventory is
link:architecture/REPOSITORY-MAP.adoc[REPOSITORY-MAP].

== Two layers

[cols="1,3",options="header"]
|===
| File | Role

| `src/EpistemicTypes.jl`
| The package module. It includes the implementation, imports each public
  binding by name, and exports it. It adds no behaviour.

| `src/core/Epistemic.jl`
| The implementation, module `Epistemic`, restored from the design thread.
  It is kept as recovered apart from three marked fixes, listed in the
  package module's header. It declares no exports of its own.
|===

The split keeps the recovered source reviewable against
`docs/recovered/` with a plain diff, while the package still presents a flat
public API. `EpistemicTypes.Epistemic` remains reachable for callers who want
the recovered namespace.

== Inside `Epistemic`

A per-row claim is a *receipt*: a `Standpoint` (tool and version, database and release, parameter
hash, normalisation), a `Warrant` (classifier and sample evidence) and a
`ProjectionY` (the taxon, rank, feature and sample claimed), bound by a
SHA-256 signature over a canonical JSON encoding.

[cols="1,3",options="header"]
|===
| Concern | Functions

| Receipts
| `make_receipt`, `verify_receipt`; the CSV-portable wire form
  `encode_avec_fibre` / `parse_avec_fibre` (base64url of the canonical JSON).

| Policy and decision
| `ThresholdPolicy`, `passes_gates`, `highest_warranted_rank`, `epi_status`,
  `disambiguate_zero` (`:true_absence` vs `:undetected`).

| Residuals
| `ResidualInfo`, `residual_info`: a per-row summary of what the
  classifier left unresolved.

| Cross-run safety
| `can_merge`, `lowest_common_rank`: refuse merges across standpoints that do
  not share a judgement surface.

| Bulk verification
| `ComputeBackend`, `bulk_verify!`. `CPUBackend` is implemented. The TPU, NPU
  and VPU backends exist so that a request for one fails loudly instead of
  falling back silently.
|===

Derived status is never stored in a receipt. It is computed from the raw
fields at analysis time, so a receipt stays valid when a policy changes.

== Dependencies

`Base64`, `Dates` and `SHA` from the standard library, and `JSON3` for the
canonical encoding.

== Tests

`test/runtests.jl` runs `Aqua.test_all`, then every `test/cases/*.jl` in
sorted order. `00-fixtures.jl` defines the shared standpoints and projection. The
others cover one concern each: `receipts.jl`, `policy.jl`, `status.jl`,
`merge.jl` and `backends.jl`.
