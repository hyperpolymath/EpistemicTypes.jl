Per-row claims with receipts for taxonomic tables: which tool, database and parameters produced a call, whether the evidence warrants it and at what rank, what is left unresolved below it, and whether two runs can be analysed together.

== What it does

A classifier writes one taxon per row. It does not write down whether that
call should be believed. EpistemicTypes adds that record, one row at a time:

* a *receipt* that binds the call to its origin: the *standpoint* (tool,
  version, database, release, parameter hash, normalisation), the *warrant*
  (the classifier's own numbers and the sample gates) and the *projection*
  (taxon, rank, feature, sample), sealed with a SHA-256 digest;
* an *epistemic status* for each row: `:Factive`, `:Belief`, `:Collapsed` or
  `:SansFibre`;
* the *residual* below the warranted rank, where "novel" is reachable only
  after the contamination gates pass;
* a *merge verdict* for two runs: `OK`, `OK_COLLAPSE` to a shared rank, or
  `REFUSE`.

Every decision is a constant-time function of one row. Statistics,
alignment, denoising and phylogenetics stay in the tools that do them
(DADA2, vsearch, MAFFT, IQ-TREE, EPA-ng); this package records and checks
what those tools concluded.

== Quick start

[source,julia]
----
using EpistemicTypes

k = Standpoint(tool = "dada2", tool_ver = "1.28.0",
               db_key = "pr2", db_release = "5.0.0",
               params_hash = "sha256:...", normalisation = "none")

w = Warrant(boot_min = 0.90,    # classifier confidence, on 0–1
            depth = 500,        # reads for this feature in this sample
            neg_leak = 0.0,     # fraction seen in the negative control
            chimera = false)

y = ProjectionY(taxon = "Giardia", rank = "Genus",
                feature_id = "ASV0001", sample_id = "S01")

r = make_receipt(k, w, y)
verify_receipt(r)                                  # true

pol = ThresholdPolicy()
epi_status(r, pol)                                 # :Factive
highest_warranted_rank(k, w, pol)                  # "Genus" (0.90 < 0.98 for Species)
----

=== Status is decided in a fixed order

`epi_status` checks the digest, then the sample gates, then the rank
thresholds, and stops at the first failure:

[cols="1,3"]
|===
| Status | Meaning

| `:SansFibre` | The digest does not match the contents. Nothing else is asked.
| `:Collapsed` | The digest matches but a sample gate failed (depth below
                 `depth_min`, negative-control leakage above `neg_leak_max`,
                 or a chimera flag). There is residue but no claim.
| `:Belief`    | Gates pass; the classifier clears no rank threshold.
| `:Factive`   | Gates pass and the classifier clears the threshold at some rank.
|===

The sample gates outrank the classifier. A bootstrap of 1.0 on three reads is
`:Collapsed`. Editing any field of a stored receipt makes it `:SansFibre`.

=== Residuals: "novel" has to be earned

[source,julia]
----
residual_info(r; named_candidates_at_species = 0, gates_ok_for_novel = true)
# warranted_rank = "Genus", status = :Factive, residual_has_novel = true

residual_info(r; named_candidates_at_species = 0, gates_ok_for_novel = false)
# contam_flag = true, residual_has_novel = false
----

A row is flagged novel only when its parent clade is `:Factive`, no named
species clears the species threshold, and the caller's contamination checks
passed. When those checks fail, the same evidence is reported as possible
contamination.

`disambiguate_zero` makes the same distinction for an empty cell: a zero is
`Val(:true_absence)` only when the sample had the depth to detect the taxon,
and `Val(:undetected)` otherwise.

=== Receipts in a table column

[source,julia]
----
s = encode_avec_fibre(r)   # "echo:v1?k={...}&w={...}&y={...}&sig=sha256:..."
verify_receipt(parse_avec_fibre(s))                # true
----

A typical receipt is about 350 bytes. It contains commas and double quotes,
so write it as a quoted CSV field. R's `write.csv`, pandas, and Protoctist's
ECSV writer all do this by default.

=== Can two runs be pooled?

[source,julia]
----
can_merge(manifest_a, manifest_b)
# (status = "OK",)
# (status = "OK_COLLAPSE", collapse_to = "Domain", reason = "db_release_mismatch")
# (status = "REFUSE", reason = "normalisation_mismatch", details = "rarefy vs rss")
# (status = "REFUSE", reason = "no_common_rank", details = "")
----

A manifest is a `Dict` with `"normalisation"` and
`"db" => Dict("key", "release", "ranks")`. Differing normalisation refuses
relative-abundance pooling. A different database or release collapses both
runs to a rank both ladders carry, the coarsest one, and refuses when they share none.

== Where it sits in a pipeline

[cols="1,2,2"]
|===
| Tool | What it provides | Join

| DADA2 `assignTaxonomy(..., outputBootstraps = TRUE)`
| Per-rank bootstrap, integer 0–100
| Divide by 100 into `boot_min`, using the bootstrap at the rank you claim.

| vsearch `--usearch_global --userfields query+target+id+qcov`
| Percent identity and query coverage, 0–100
| Divide both by 100 into `id` and `cov`.

| Feature table and negative controls
| Per-sample read counts
| `depth`, and the control fraction as `neg_leak`.

| UCHIME / `removeBimeraDenovo`
| Chimera calls
| `chimera`.

| Protoctist.jl
| Lineage tables, trees, iTOL export
| Carries receipts and statuses per row and rolls them up a taxonomy.
|===

`ThresholdPolicy` defaults are DADA2 Species 0.98, Genus 0.88, Class 0.75,
Division 0.70; vsearch identity/coverage Species 0.99/0.95, Genus 0.95/0.90,
Division 0.85/0.80; a feature needs 100 reads and at most 0.5% negative-control
leakage. `docs/EXPLAINME.adoc` gives the reasoning, and why each rank is gated
separately. All values are overridable per database and locus.

== Formal basis

The status split follows
https://github.com/hyperpolymath/epistemic-types[epistemic-types], checked in
Agda with `--safe --without-K`. There, a factive modality has a reflection
principle and a belief modality deliberately lacks one. The residual summary
follows
https://github.com/hyperpolymath/residual-evidence-types[residual-evidence-types],
where identification quantifies over every admissible candidate. The Julia
code follows these designs; it is not extracted from the proofs.

== Testing

[source,bash]
----
julia --project=. -e 'using Pkg; Pkg.test()'
----

`Aqua.test_all` (11 checks) runs first, then 89 behaviour tests: the digest
under tampering of each leg, the wire-form round trip, the gate and rank
thresholds for both tools, all four statuses, the residual and contamination
logic, and each `can_merge` verdict. One further test is marked `@test_broken`
for the wire-form limit described in the EXPLAINME.
